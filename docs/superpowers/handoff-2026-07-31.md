## What this is

A public web dashboard for a single-station hazmat team, built to replace "no formal system / tribal knowledge" tracking of:
- Gas cylinders (calibration gas) — live PSI gauges for in-use tanks, spare count, editable PSI/status, soft-delete via Retire
- Equipment (meters/detectors, PPE, tools & misc) — red/green in-service status by category, toggle + retire
- Problem notes — free-text log entries, shown on the dashboard until resolved
- Full activity log at `/log` — every tank/equipment change and problem note, auto-logged, timestamped, attributed

No login system. Anyone with the link can view and edit; every write requires typing a name (persisted to that browser via localStorage), used only for attribution — never verified identity. This was an explicit, deliberate design choice from the original brainstorming session, not an oversight.

## Tech stack

Next.js 14 (App Router, TypeScript), Tailwind CSS, `@supabase/supabase-js`, Vitest + Testing Library (83 tests, all passing at handoff time), hosted free on Vercel with a free-tier Supabase Postgres + Realtime backend.

## Architecture

`Repository` interface (`src/lib/repository.ts`) → two implementations: `InMemoryRepository` (used by all automated tests, zero network) and `SupabaseRepository` (production, `src/lib/supabaseRepository.ts`) → service layer (`tankService`/`equipmentService`/`logService`) that auto-inserts a `log_entries` row on every real tank PSI/status change and equipment status change → thin Next.js API routes (`src/app/api/...`) → React components → the dashboard (`/`) and log (`/log`) pages, both live-updating via a shared `useRealtimeRefetch` hook subscribed to Supabase Realtime.

## Known open items (not yet done)

1. **User wants a broader UI/UX pass.** Not scoped yet — should go through the brainstorming skill again to figure out what specifically needs to change before touching styles, rather than guessing.
2. `AddEquipmentForm` doesn't check `response.ok` on submit — same silent-failure class already fixed in `NewProblemForm` and the log page's resolve action (final-review fix, commit `07b0460`), but this one form was out of that fix's scope. Minor, flagged in the final review, not blocking.
3. Retired tanks/equipment become fully invisible in the UI (no "show retired" view anywhere) — this matches the spec/plan as written, not a bug, but is a plausible future product gap if the team ever wants to review what's been retired.
4. No server-side validation of enum values or cross-field ranges (e.g., nothing stops `psi > maxPsi`) — only presence/type validation exists (added in the final-review fix). Minor.
5. Supabase RLS policies are fully permissive, including `DELETE` — the soft-delete-only guarantee is enforced in app code only, not at the database level. This was an accepted tradeoff of the "no login, link is the access control" design, but worth hardening later if the accountability/audit-trail goal becomes more load-bearing than it is today.
